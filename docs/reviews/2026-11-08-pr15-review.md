## Major

### 🟠 The reused complete report prints blank, `experiments/rehearsal/app/rehearsal.css:157`

**Problem**: The globally imported print stylesheet applies `visibility: hidden !important` to every descendant of `body` on every route. Only an authorized `.preparation-sheet` restores visibility. The existing `/report` page is reused in this workspace and calls `window.print()` normally, so its complete fictional report remains hidden in print media.

**Why it matters**: The local journey advertises and retains the complete report, and CR-10 requires that artifact to remain unchanged. A user can preview the report successfully and then receive a blank print/PDF. The public application's own stylesheet is unaffected; this is a reproducible regression in the authorized local workspace, not a claim of a production outage.

**Reproduction**: Launched the existing rehearsal production build on `127.0.0.1:3002` with a simulation-only token. In headless Chromium, completed V01, opened “Preview complete report,” and confirmed `.report-document` visible on screen. After `page.emulateMedia({ media: "print" })`, that element was not visible, its computed `visibility` was `hidden`, and it had zero descendants with visible computed visibility. No provider or production service was contacted; the local server was stopped afterward.

**Suggested fix**: Scope rehearsal concealment rules to the rehearsal route using explicit route identity, while preserving the existing report print styles. Add a local-workspace browser assertion that the complete report remains visible in print media and that incidental rehearsal printing remains concealed.

## Minor

### 🟡 Edited written questions retain authored provenance, `src/lib/rehearsal/state.ts:219`

**Problem**: `editQuestion` updates the text but preserves `Written starter` for a question originally added from the authored worksheet. The resulting preparation sheet attributes user-written replacements to the application's written starter.

**Why it matters**: The sheet's origin labels are part of CR-10. This does not cause transmission or alter the fixed canonical facts, but it misrepresents where the selected wording came from.

**Reproduction**: Ran the reviewed head's reducer directly after transpiling it in memory: add `{ id: "written", text: "Which information is missing?", origin: "Written starter" }`, then dispatch `editQuestion` with `"What are the limits of this example?"`. The resulting question has the replacement text and still has `origin: "Written starter"`. The UI renders that origin on both the question choice and sheet.

**Suggested fix**: Give changed authored questions a truthful user-edit label (or `User wording`) and preserve the existing special origin for edited simulated suggestions. Cover this reducer transition and the resulting visible sheet label.
