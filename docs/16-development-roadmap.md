## Sequential critical path

Authorization → exact variant/table contract → thin authored journey → remaining rules and urgent behavior → result/evidence/report → clearing/accessibility/privacy tests → real build evidence → deployment/deck/video → approved submission. There are no parallel Developer A/B lanes and no assumed second developer review. Do not start by building all UI first while deferring integration.

The builder owns frontend, domain logic, validation, tests, configuration and submission preparation. Codex may assist when work is authorized, but assistance does not create another person's available hours or independent clinical/human evidence. Split work into small verifiable slices and maintain a short daily handoff note for the next session.
